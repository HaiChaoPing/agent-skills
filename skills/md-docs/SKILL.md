name: md-docs
description: 使用markdown编写文档时使用
---

1. 明确当前场景和目标用户。当且仅当编写面向人类的文档时使用。
- 反例：在类似`superpowers`的长工作流程中编写plan，spec等主要面向agent的文档时，不适用本skill
- 反例：在类似`matt pocock`的场景中编写任务记忆，经验等文档时，不适用本skill

2. 在文档开头写一个目录，让读者能快速索引到标题，找到自己要参考的重点。标题应该简洁，突出重点，并擅用多级标题分割语义。

~~~
# 文档标题

## 目录

- [安装](#安装)
- [配置](#配置)
  - [基础配置](#基础配置)
- [API](#api)
~~~

3. 将文档明确分为面向使用用户和深度用户（或开发者，维护者）的片段。具体来说，一般默认放在前面的内容都面向使用用户，在最后添加一个专门面向深度用户/开发者/维护者的部分。
- 典型的，对于项目中使用的工具说明，应该分为使用和解释两部分，使用部分主要使用带注释的shell或项目语言片段展示工具用法，在最后的开发者部分解释不常用的参数，数据来源，设计原理等内容。
