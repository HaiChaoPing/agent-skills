description: 编写面向人类读者的 Markdown 文档（README、使用说明、教程、工具文档）时使用。规定目录结构和"使用者在前、开发者在其后"的分层写法。面向 agent 的 plan/spec/任务记忆不适用。
---

1.  仅当编写面向人类的文档时使用本skill。plan、spec、任务记忆等面向agent的中间产物不适用。
2.  将文档明确分为面向使用用户和深度用户（或开发者，维护者）的片段。一般默认放在前面的内容都面向使用用户，在最后添加一个专门面向深度用户/开发者/维护者的部分。
- 典型的，对于项目中使用的工具说明，应该分为使用和解释两部分，使用部分主要使用带注释的shell或项目语言片段展示工具用法，在最后的开发者部分解释不常用的参数，数据来源，设计原理等内容。
3.  在开头写目录，让读者能快速索引到标题。标题应该简洁，突出重点，并擅用多级标题分割语义。
2.1 目录本身要尽可能形成文档的domain-model
2.2 标题应该简洁，突出重点，积极使用多级标题分割语义
2.3 即使文档较短，也应该写目录
2.4 目录格式参照下列例子。注意目录在最前面，没有标题，目录本身也不在标题系统内

~~~
- [文档标题](#文档标题)
  - [使用](#使用)
  - [API](#api)
- [开发者内容](#开发者内容)


# 文档标题

## 使用

## api

# 开发者内容
~~~
